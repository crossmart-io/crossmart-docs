# crossmart-docs

The documentation site for [Crossmart](https://crossmart.io), the open-source multichannel
platform for sellers and their AI agents, served at
[docs.crossmart.io](https://docs.crossmart.io).

Built with [Starlight](https://starlight.astro.build) (Astro), as decided in the backend
repository's ADR 0013.

## Develop

Requires Node.js 22.23+ (see `.nvmrc`) and pnpm.

```bash
pnpm install
pnpm dev          # http://localhost:4321
pnpm format       # Prettier
pnpm build        # type check, build into dist/ and validate links between pages
pnpm check:links  # after a build: check every internal link and anchor in dist/
```

`pnpm build` fails on a broken link or anchor in the pages (`starlight-links-validator`).
`pnpm check:links` also covers the generated API reference, which that validator can't see. The
build also writes `llms.txt`, `llms-full.txt` and `llms-small.txt` for AI agents.

## Structure

| Path                             | What                                                                   |
| -------------------------------- | ---------------------------------------------------------------------- |
| `src/content/docs/`              | Pages, in Markdown or MDX; the path is the URL                         |
| `src/content/docs/developers/`   | The developer guide: API overview, quickstart, SDKs, MCP               |
| `src/content/docs/sellers/`      | The seller guide: stores, publishing, listings, pricing, stock, orders |
| `src/content/docs/channels/`     | One page per channel                                                   |
| `src/content/docs/agents/`       | AI agent setup guides and the Crossmart skill                          |
| `src/content/docs/integrations/` | Integrations such as n8n                                               |
| `openapi/crossmart.json`         | Snapshot of the API's OpenAPI spec                                     |
| `astro.config.mjs`               | Site config and the sidebar                                            |
| `src/styles/theme.css`           | Brand colours on Starlight's theme variables                           |

The developer, agent, channel and n8n pages follow `docs/developers/`, `docs/channels/`,
`skills/` and `sdks/*/README.md` in [crossmart-io/crossmart](https://github.com/crossmart-io/crossmart).
Change both together. Ask Crossmart answers from these pages: after a change, rebuild its knowledge
index in the backend (`pnpm knowledge:build`).

### API reference

The pages under `/developers/api/` are generated by
[starlight-openapi](https://github.com/HiDeoo/starlight-openapi) from `openapi/crossmart.json`.
After an API release, refresh the snapshot and commit it. When the spec names no `servers`,
the sync adds `https://api.crossmart.io` so code samples point at the real API.

```bash
pnpm openapi:sync                                                      # from api.crossmart.io
CROSSMART_OPENAPI_URL=http://localhost:3000/api/docs-json pnpm openapi:sync   # from a local API
```

## Configuration

Build-time variables, read by Astro when the site is built (see `.env.example`). They are public:
their values end up in the static pages.

| Variable                   | What                                                                                                                             |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `PUBLIC_GA_MEASUREMENT_ID` | Google Analytics 4 Measurement ID (`G-XXXXXXXXXX`). Unset or empty: no analytics script, no cookie banner, no "Cookie settings". |

### Analytics and consent

The docs share crossmart.io's analytics setup and can use the same GA4 property. GA4 runs behind
Google Consent Mode v2 in its basic form: gtag.js loads only after the visitor chooses "Accept"
in the cookie banner, so no request reaches Google before consent. "Accept" grants
`analytics_storage` only; ad storage stays denied. The choice is kept in localStorage and
re-applied on every page. "Cookie settings" under each page reopens the banner, and
withdrawing consent deletes the `_ga` cookies. The banner links to the
[privacy policy](https://crossmart.io/privacy/).

- Config and event names: `src/data/analytics.ts`. Banner copy: `src/data/consent.ts`.
- The banner and the link come from a `Footer` override (`src/components/Footer.astro`); the
  logic is in `src/scripts/analytics/`.
- Events: `sign_up_click` (links to the app) and `github_click`, with the link's text.

## Deploy

The site is static. The `Dockerfile` builds it and serves `dist/` with nginx on `$PORT`
(`deploy/nginx.conf.template`), the same way as the marketing site. On Railway, set
`PUBLIC_GA_MEASUREMENT_ID` on the docs service; the `Dockerfile` takes it as a build argument,
so a change needs a redeploy.
